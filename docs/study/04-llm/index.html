LLM 推理 Pipeline

用户输入 "Hello, how"
  │
  ▼
┌─ Tokenizer ──────────────────────────────────────────┐
│  编码 → token ids: [15496, 11, 423, ...]             │
└──────────────────────────────────────────────────────┘
  │
  ▼
┌─ Prefill (并行) ─────────────────────────────────────┐
│  Prompt 所有 token 并行过 Transformer                 │
│  建立 KV Cache: 每个 Decoder Layer 存储 K/V           │
│  输出: 最后一个 token 的 logits                       │
└──────────────────────────────────────────────────────┘
  │
  ▼
┌─ Sample ─────────────────────────────────────────────┐
│  Top-K / Top-P / Temperature 采样                     │
│  选出下一个 token: "are"                              │
└──────────────────────────────────────────────────────┘
  │
  ▼
┌─ Decode (串行, 逐 token) ────────────────────────────┐
│  每次只算新 token 的 QKV                               │
│  Attention: concat(历史 K/V, 新 K/V)                   │
│  利用 KV Cache 避免重算 → 大幅减少 Prefill 之外的 FLOPs│
│  重复直到  或 max_len                             │
└──────────────────────────────────────────────────────┘
  │
  ▼
输出: "Hello, how are you?"

面试重点

Prefill 和 Decode 的本质区别？
Prefill：并行处理 prompt token，计算密集（compute-bound），利用 GEMM 批量优势。Decode：逐 token 串行，内存密集（memory-bound），瓶颈在逐层加载权重。
KV Cache 为什么重要？
自回归推理每个新 token 的 attention 都需要所有历史 token 的 K/V。不缓存则每个 decode 步都重算全部 history，总复杂度从 O(n²) 暴增到 O(n³)。
INT4 量化如何实现？
权重量化为 4-bit（16 个值），推理时做 dequant 恢复成 FP16/BF16 再计算。MNN 支持 AWQ/HQQ/GPTQ 等方案，核心是找到最优 scale/zero 使得量化误差最小。
推测解码加速原理？
小模型快速生成 K 个候选 token → 大模型并行验证 → 接受正确的 → 拒绝错的从第一个错误处重新生成。一次验证多 token，突破自回归的串行瓶颈。

学习路径建议

  1. LLM 导出流程：llmexport.py → model_mapper.py → transformers.py → ONNX → MNN Converter
  2. 推理引擎：llm.cpp 的 Prefill / Decode 主循环
  3. KV Cache：KVCache 内存分配 + Past K/V 拼接
  4. 采样器：Top-K / Top-P / Temperature 实现
  5. 量化：AWQ / HQQ / GPTQ 原理 + 导出
  6. 推测解码：EAGLE / Lookahead 调度机制
  7. Benchmark：TTFT / TPOT / TPS 性能指标
