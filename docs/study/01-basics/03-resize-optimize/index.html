Phase 1：形状推导

主循环（对每个 OpCacheInfo）

for (int i=0; i<infos.size(); ++i) {
    auto& info = infos[i];

    // Step 1：重置输出 Tensor 状态
    //   - 引用计数 >1（被共享） → 重新创建描述
    //   - 其他 → 清空 backend 和 mem
    for (auto t : info.outputs) {
        setBackend(nullptr);
        mem = nullptr;
    }

    // Step 2：检查 shape 是否变化
    bool needCompute = !info.computeCache.match(info.inputs, compared);

    // Step 3：变了 → 调用 SizeComputer 算输出 shape
    if (needCompute) {
        SizeComputer::computeOutputSize(op, inputs, outputs);
        //   dispatch 链：
        //     computer = SizeComputerSuite::search(op->type())
        //     computer->onComputeSize(op, inputs, outputs)

        adjustTensorForCompability(outputs);
        info.computeCache.insert(inputs);     // 缓存当前 shape
    }

    // Step 4：CONSTANT Op → 用 CPU 直接算出常量值
    if (info.type == CONSTANT && needCompute) {
        GeometryComputer::search()->onCompute()
        backupBackend 分配内存 + onExecute()
    }
}

SizeComputer::computeOutputSize(op, inputs, outputs)

Conv 形状推导示例

ConvolutionSizeComputer::onComputeSize(op, inputs, outputs) {
    kX = kernelX, kY = kernelY, strideX, strideY

    SAME:  oh = ceil(input_h / stride_h)
    VALID: oh = ceil((input_h - kernel_h + 1) / stride_h)
    CAFFE: oh = (input_h + 2*pad_h - kernel_h) / stride_h + 1

    outputs[0]->dim = [batch, outputCount, oh, ow]
}

Phase 2：Geometry 变换

三种拆分规则

① 计算密集型 → Im2Col + MatMul

Conv2D      → Im2Col + MatMul + Col2Im
ConvTranspose → Im2Col + MatMul
FullyConnected → Reshape + MatMul
BatchMatMul → MatMul（多维转二维）
// 目的：复用 GEMM 优化

② 内存布局型 → Region（不产生新 Command）

Concat → 填 regions[]（各输入拼到不同偏移）
Slice  → 填 regions[]（从输入截取一段）
Pad    → 填 regions[]（输入写到输出中间）
// 不做数学运算，只描述"谁写到哪"

③ 逐元素型 → 透传或拆 BinaryOp

ReLU      → 透传（本身已是基础 Op）
BinaryOp  → 透传（Add/Mul/Sub）
BatchNorm → Mul + Add
// 后端直接实现 BinaryOp

Region / Raster

Region：数据搬运的描述

struct Region {
    View src;              // {offset, stride[3]}
    View dst;              // {offset, stride[3]}
    int32_t size[3];       // 三个维度长度
    Tensor* origin;        // 源 tensor
};

Region 描述"从 origin[src.offset : src.stride] 范围 size，搬到 dst.offset : dst.stride"。offset 和 stride 都是元素单位，代码中乘以 bytes 转字节。

Raster：执行 Region 的 Op

ErrorCode CPURaster::onExecute(inputs, outputs) {
    for (auto& slice : output->regions) {
        srcPtr = origin->host() + slice.src.offset * bytes;
        dstPtr = output->host() + slice.dst.offset * bytes;
        _blit(slice, bytes, srcPtr, dstPtr);  // 三维循环 memcpy
    }
}

_createExecutions — 4 层优先级

for 每个 Command:
    ① executionCache 缓存（上次 resize 的）
    ② KV Cache 克隆（LLM Attention 共享）
    ③ primary Backend 创建（GPU/OpenCL/Metal）
    ④ backup CPU 兜底

    都不行 → return NOT_SUPPORT

_allocForTensor — 引用计数内存复用

// Step 1：统计 useCount
for 每个 Command:
  for 每个 workInputs: des->useCount += 1

// Step 2：分配 + 释放
for 每个 Command:
  _allocTensor(inputs)   // 仅 mem==null 才分配
  _allocTensor(outputs)
  execution->onResize()
  _releaseTensor(inputs) // useCount--，归零释放

// _allocTensor：mem 已有→复用，mem 为空→onAcquireBuffer

面试重点

encode 和 execute 什么区别？
encode = 编译期，形状推导 + Op 分解 + 内存规划。只在 resize 时调用。execute = 运行期，逐条执行 Command。每次 runSession 都调用。encode 产出 CommandBuffer，execute 消费 CommandBuffer。
Session::resize 为什么分 encode 和 allocMemory 两步？
encode 不依赖硬件，纯数学计算 + 算法分解；allocMemory 依赖具体后端，需要创建 Execution 和分配内存。shape 没变时跳过 encode 只走 allocMemory，省掉不必要的形状推导和 Op 分解。
SizeComputer 的调用链？
encode → shapeComputeAndGeometryTransform → SizeComputer::computeOutputSize → SizeComputerSuite::search(op->type()) → mRegistry[op->type()] → computer->onComputeSize()。每个 OpType 对应一个 SizeComputer，本质是数学公式。
Geometry 拆分规则是什么？
三类：计算密集型拆 Im2Col+MatMul 复用 GEMM；内存布局型转 Region 由 Raster 统一执行；逐元素型透传。后端只要实现 MatMul + BinaryOp + Raster 三种基础能力。
Region 和 Raster 分别是什么？
Region = "图纸"，描述数据从源到目标的带步长拷贝。Geometry 阶段填好。Raster = "施工队"，运行时遍历 Region 执行 memcpy。offset/stride 都是元素单位。
_createExecutions 的优先级？
4 层：① executionCache 缓存 → ② KV Cache Attention 克隆 → ③ primary Backend 创建 → ④ backup CPU 兜底。全失败报 NOT_SUPPORT。
allocMemory 每次都开辟新内存吗？
不一定。首次全部分配；shape 没变跳过；shape 变了清空重分配。引用计数管理：useCount 归零立即释放供复用。是静态内存规划，不是动态 malloc/free。
Region 为什么能表达这么多算子？
Concat/Slice/Pad/Crop 本质都是数据重排不做数学计算。差异只是 offset/stride 参数不同，没有本质区别。Region 用 6 个整数就能描述任意 N 维数据子集拷贝。

深度总结

encode/allocMemory 两阶段分离（数学 vs 硬件）
静态/动态模型分路径（needComputeGeometry）
OpResizeCache 增量检测（match/insert/close）
SizeComputer 形状推导（70+ 子类，数学公式）
SizeComputerSuite 注册表（search O(1) 哈希查找）
GeometryComputer Op 分解（Conv→Im2Col+MatMul 等）
常量折叠：encode 阶段 CPU 执行 + STATIC 内存写入
CONTENT_NOT_CHANGE 脏标记链（避免重复计算）
_createExecutions 4 层优先级（cache→KV→primary→CPU）
_SetTensorBackend 标记 Tensor 归属 Backend
_InsertCopy 跨后端 Wrap（workInputs 赋值点）
_allocForTensor 引用计数内存复用（useCount）
三种内存类型（STATIC / DYNAMIC_SEPERATE / DYNAMIC）
opFuse 编译期 GPU 逐元素融合（MNN_BUILD_CODEGEN）
fixResizeCache group 固定内存（避免重复分配）
