KVMeta 结构 — 缓存生命周期簿记

// KVMeta.hpp:17
struct KVMeta {
    size_t block = 4096;     // 分配粒度
    size_t previous = 0;     // 已缓存的 KV 位置总数
    size_t remove = 0;       // 要从开头移除的位置数 (滚动窗口)
    size_t add = 0;          // 要追加的新位置数
    int* reserve = nullptr;  // 保留段 [n_reserve] 个 (start, len) 对
    int n_reserve = 0;
};

synchronize():  previous = previous - remove + add
// Prefill 后:  add=seq_len,  remove=0 → previous = seq_len
// Decode 后:   add=1,       remove=0 → previous = seq_len + t
// 滚动窗口:    add=1,       remove=1 → previous 不变

KV Cache 内存布局 (按量化模式)

未量化 Key:    [maxlen/hP, headDim/lP, hP, lP]
  hP=8 (ARM64), 位置按 8 个一组打包, 512 个位置 → 64 个 hP 块

未量化 Value:  [headDim/hP, maxlen/lP, hP, lP]
  与 Key 维度对调! headDim 是外层, maxlen 是内层

INT8 Key:      [maxlen/hP8, blockNum, (headDim/blockNum)/lP8, hP8, lP8]
  额外 2×hP8×sizeof(float) 存储 scale + bias

Flash Attention Value:
  [kvHead, UP_DIV(maxlen, flashBlock), UP_DIV(headDim, hP),
   UP_DIV(flashBlock, lP), hP, lP]
  flashBlock = 64 (典型值)

ProcessKey (TQ3):
  bytesPerSeq = (headDim / blockSize) × bytesPerBlock
  直接按序写入每行字节 (3.5 bits/value 压缩格式)

  MNNQuantAttentionKey → 打包为 INT8 GEMM 格式 + scale/bias

Prefill 流程 (llm.cpp:930-996)

generate(input_embeds, max_tokens):
  1. setKVCacheInfo:  mMeta->add = seq_len

  2. forwardVec(input_embeds):            // ★ Prefill
       gen_attention_mask(seq_len)        // 因果 mask (下三角)
       gen_position_ids(seq_len)          // 位置 [0, 1, ..., seq-1]
       forwardRaw(embeds, mask, pos)      // 运行 MNN 图
       mMeta->synchronize()               // previous += seq_len

  3. updateContext(seq_len, 0):           // all_seq_len += seq_len

  ★ 全 prompt 并行处理, 建立完整 KV Cache

分块 Prefill (长 Prompt 优化)

// llm.cpp:624
如果 prompt 太长, 按 mBlockSize 分块:

mMeta->add = blockSize;
for i in [0..blockCount]:
  forwardRaw(embeddings[i], mask, pos)
  updateContext(blockSize, 0)   // 不增加 gen_seq_len (跳过解码)

★ 每块的 KV 都追加到缓存, 下一块能用到历史的 K/V

Decode 流程 (generate.cpp:42-86)

ArGeneration::generate():
  while (len < max_token):
    1. sample(logits)                     // 从最后 logit 取 next token
       → 采样策略: Top-K, Top-P, Temperature

    2. output_tokens.push_back(token)

    3. updateContext(0, 1)                // gen_seq_len += 1

    4. forwardVec({token}):               // ★ Decode
         mMeta->add = 1                   // 追加 1 个 KV 位置
         gen_attention_mask(1)            // 单 token, 无 mask
         gen_position_ids(1)              // 位置 = all_seq_len

    5. updateContext(1, 0)                // all_seq_len += 1

Prefill vs Decode 本质区别

PrefillDecode
输入prompt 全部 token (N 个)1 个新 token
并行性N 个 token 并行 (compute-bound)串行 (memory-bound)
KV Cache新建, 追加 N 个位置追加 1 个位置
AttentionQ[N,d] × K[N,d]^T (完整矩阵乘)Q[1,d] × K[prev+N,d]^T (向量 × 矩阵)
瓶颈计算密集: GEMM 大矩阵内存密集: 逐层加载权重
MNN 优化分块 Prefill, Flash AttentionTQ3/TQ4 量化 KV Cache, 推测解码
