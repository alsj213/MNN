Winograd 卷积 — 用加法换乘法的数学技巧

深度完成

为什么需要 Winograd

直接卷积 (3×3, stride=1): 每输出点做 9 次乘法
Winograd F(2×2, 3×3):      每 4 个输出点只做 16 次乘法

对比: 直接卷积 4 个输出点 = 4×9 = 36 次乘
      Winograd = 16 次乘 → 乘次数减少 2.25×!

核心公式

Y = A^T [ (G · g · G^T) ⊙ (B^T · d · B) ] · A

  d = 输入 tile (α×α)      g = 权重 (r×r)
  G = 权重变换矩阵          B = 输入变换矩阵
  A = 输出变换矩阵          ⊙ = 逐元素乘法

  参数:  F(m, r)  m=输出大小  r=卷积核大小
  α = m + r - 1  (变换空间维度)

  F(2,3): α=4, A[4×2], B[4×4], G[3×4]
  F(4,3): α=6, A[6×4], B[6×6], G[3×6]

三阶段执行流程

阶段 1: 输入变换 V = B^T · d · B（每次推理, 在线）

// WinogradOptFunction.cpp — _sourceTransformUnit4x4 (F(2,3))
// B^T 的系数在 interp=1 时退化为小整数 {0, ±1}

输入 tile d[4×4]:
  s0  s1  s2  s3    一维变换 BT*d (应用于列), B 是 4×4:
  ...                     m0 = s0 - s2       (系数: 1, 0, -1, 0)
  ...                     m1 = s1 + s2       (系数: 0, 1, 1, 0)
                          m2 = s2 - s1       (系数: 0, -1, 1, 0)
                          m3 = s3 - s1       (系数: -1, 1, 0, 1)

然后对行做同样的变换: V = BT · (BT · d)^T

F(4,3) 系数变大:
  m0 = s0*4 - s2*5 + s4          (系数: 4, 0, -5, 0, 1)
  m1 = (s1+s2)*(-4) + (s3+s4)    (系数: 0, -4, -4, 1, 1)
  m2 = (s1-s2)*4 + (s4-s3)
  ...
  m5 = s1*4 - s3*5 + s5

★ 全用加减和移位, 零乘法! 只有常数系数

阶段 2: 逐元素乘法 M = U ⊙ V (每次推理, 在线)

// ConvolutionPackWinograd.cpp — 对 α² 个变换点各做一次小 MatMul
// U 形状: [α², ocDiv4, icDiv4, pack, pack]   ← 变换后的权重
// V 形状: [α², ic, eP]                        ← 变换后的输入
// M 形状: [α², oc, eP]

for tile in 0..alpha²:
    MNNPackC4ForMatMul_A(V_tile)   // Pack 输入
    MNNPackedMatMul(U_tile, V_tile_packed)  // 矩阵乘法
    → M_tile[oc, eP]

// α² = 16 for F(2,3), 36 for F(4,3)
// 每个 tile 是独立的 [ic] × [oc] 小 GEMM

阶段 3: 输出变换 Y = A^T · M · A (每次推理, 在线)

// WinogradOptFunction.cpp — _destTransformUnit4x2 (F(2,3))
// A^T 应用于 M 的每一列

A^T 的系数 (同样是小整数):
  m0 = s0 + s1 + s2      (系数: 1, 1, 1)
  m1 = (s1 - s2) + s3    (系数: 0, 1, -1, 1)

输出 tile [2×2] ← 从 α×α=4×4 中间结果还原

F(4,3) 的 A^T:
  m0 = s0 + s1 + s2 + s3 + s4       (5 元素求和)
  m1 = (s1-s2) + (s3-s4)*2          (差分 ×2)
  m2 = (s1+s2) + (s3+s4)*4          (和 ×4)
  m3 = (s1-s2) + (s3-s4)*8 + s5     (差分 ×8)

★ 输出变换同样全是加减和移位!

离线权重变换: U = G · g · G^T（只做一次）

// WingoradGenerater.cpp:230-275 — transformWeight
// 在构造/onResize 时完成, 推理时不再计算

原始权重 g[oc, ic, kh, kw]:
  for each (oc_group, ic_group):               // 每 4×4 个通道
    M  = G × kernel   (矩阵乘)                  // G[3×4] × kernel[4×4]
    U  = M × G^T      (矩阵乘)                  // M[4×4] × G^T[4×4]
    → 变换后权重: [alpha², ocDiv4, icDiv4, pack, pack]

// G 矩阵包含分数系数 (dividedInG=true)
// 所以 U 的元素多是 FP32 浮点数, 不是小整数

G 矩阵是如何生成的

// WingoradGenerater.cpp:139-216
// Cook-Toom 算法: 取 m+r-1 个插值点, 构造范德蒙德矩阵

F(2,3): alpha=4, 插值点: {0, -0.5, 0.5, -1}

  矩阵 A[4×2]:  y∈[0,1], x∈插值点
    A[y][x] = a[x]^y       (范德蒙德格式: 1, a, a², ...)

  矩阵 G[3×4]:  r=3 行, alpha=4 列
    与 A 相同的范德蒙德基础, r=3 行

  矩阵 B[4×4]:  通过拉格朗日基 + 多项式商构造

  dividedInG=true: G 包含有理数 (1/2, 1/4 ...)
  → A 和 B 保持小整数 (便于在线变换的 NEON 加速)

F(2,3) vs F(4,3) 的选择

// ConvolutionPackWinograd.cpp:142-214 — bestWinogradUnit

supportSu = {4, 6, 8} → F(2,3), F(4,3), F(6,3)

for unit in [2..maxUnit]:
    alpha = unit + kernelSize - 1
    if alpha not in {4, 6, 8}: continue

    // 成本模型:
    originCost   = ic * oc * kh * kw * oh * ow    (直接卷积 FLOPs)
    winogradCost = 变换开销 + 乘法开销 + 逆变换开销

    reduceRate = originCost / winogradCost

选择 reduceRate 最大的 unit
如果 maxRate < 1.0 → 退回到 Im2Col+GEMM

winogradMemoryLevel 提示:
  != 3 → maxUnit=2, 只能选 F(2,3)  (节省内存)
  == 3 → 可尝试 F(4,3), F(6,3)

Pack vs PackFree 的差异

PackWinograd (ARM/通用):
  mGemmMidBuffer: [threadNumber, alpha, ePack*ic4*pack, bytes]
  ← 有中间 GEMM buffer, Pack 后再 MatMul

PackFreeWinograd (AVX-512/SSE):
  mGemmMidBuffer: [1] ← 几乎为空!
  ← 直接用 MNNPackedMatMulOC16/32/48Functions
  ← 跳过 Pack A 步骤, 直接原地 MatMul
  ← 内存节约 ~30%, 适合寄存器充裕的 AVX-512

INT8 Winograd 的特殊处理

// ConvInt8Winograd.cpp

1. 权重反量化: INT8 → FP32
2. FP32 域做 G·g·G^T 变换
3. 重新量化: FP32 → INT8 (逐变换点 scale)
4. 预计算偏置: offset = sum(quanData × (-inputPoint[a]))

执行时:
  输入变换: FP32 (与 FP32 路径相同)
  量化输入: MNNFloat2Int8
  GEMM:      INT8 GEMM kernel
  输出变换: FP32
  合并输出: MNNMatrixAdd + MNNFloat2Int8

面试重点

Winograd 为什么能减少乘法？
利用多项式插值原理，将卷积转化为变换空间中的逐元素乘法。F(2,3) 用 16 次代替 36 次乘，代价是更多的加法。因为加法远快于乘法 (NEON fadd 比 fmla 延迟低 2-3×), 总计算量减少。
为什么要分离 G 和 B/A 的有理数？
dividedInG=true 时, G 包含分数系数, A 和 B 保持小整数。权重变换只做一次 (离线), 代价可接受; 输入/输出变换每次推理都做, 小整数可用 NEON add/sub/shift 实现, 零浮点乘法。
为什么 stride != 1 不能用 Winograd？
Winograd 要求输出 tile 内相邻像素共享重叠的输入区域。stride > 1 时相邻输出之间的输入重叠不够, F(m,r) 的加速比下降, 甚至不如 Im2Col。
Winograd vs Im2Col+GEMM 选择策略？
kernel=3×3, stride=1, dilation=1 → 同时评估 Winograd 和 Im2Col 成本模型 → 选 reduceRate 最高的。kernel≠3 或 stride≠1 → 直接 Im2Col。FP16 (ARM82) 禁用 F(6,3) 因为精度不足。

深度总结

✅ 数学原理: A^T[(GgG^T)⊙(B^TdB)]A, Cook-Toom 多项式插值
✅ 矩阵生成: 范德蒙德 → A/G, 拉格朗日 → B, dividedInG 策略
✅ 权重变换: G·g·G^T 离线一次完成, 输出 [α², oc4, ic4, p, p]
✅ 输入变换: B^T·d·B 在线, NEON 加减移位, 零浮点乘法
✅ 逐元素乘法: α² 个小 GEMM, Pack + MatMul
✅ 输出变换: A^T·M·A, 同样是纯加减
✅ F(2,3)/F(4,3) 选择: 成本模型 reduceRate, maxRate<1 退回 Im2Col
✅ Pack vs PackFree: buffer 占用差异, AVX-512 免 Pack
