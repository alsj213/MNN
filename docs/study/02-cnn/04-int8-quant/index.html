量化公式

// 标准对称量化 (MNN 默认)
int8_value = round(FP32_value / scale)       // scale 是 FP32
FP32_value = int8_value × scale               // 去量化

// TF 风格 (uint8, 零点 ≠ 0)
float = (uint8_value - zero_point) × scale

// 去量化在 GEMM 内部的公式 (ConvInt8TiledExecutor):
value = dstInt32 × scale_weight × inputScale    // GEMM 累加结果 × 缩放
      + srcSum × weightBias                       // 输入和补偿项
      + inputBias × weightKernelSum               // 非对称激活偏置
      + bias                                       // 卷积偏置

ConvInt8TiledExecutor 执行流程

// ConvInt8TiledExecutor.cpp:1531+

动态量化路径 (MNN_LOW_MEMORY):
  ① BatchAsyDynamicQuant: 运行时算 min/max → scale/zero
  ② MNNFloat2Int8: FP32 输入 → INT8

  ③ Im2Col: MNNPackC4Int8ForMatMul_A → [blockL, EP, SRC_UNIT]
  ④ MNNSumByAxisLForMatmul_A: 算 Σ(input) × inputScale (去量化补偿项)
  ⑤ Int8GemmKernel:
       for each output tile:
         int32 accum += Σ(int8_src × int8_weight)
         FP32 = accum × scale_w × scale_in + compensation + bias
  ⑥ 可选: MNNFloat2Int8  → INT8 输出

非动态路径 (离线量化):
  输入已是 INT8, 跳过 ①②, 直接从 ③ 开始

INT8 GEMM 内循环 (标量参考实现)

// Int8FunctionsOpt.cpp:1531  MNNGemmInt8AddBiasScale_16x4_Unit

for block in [0..blockNum]:                    // 分组量化, 每组独立 scale
  for sz in [0..src_depth_quad]:
    for j in [0..UNIT]:                         // 4 个输出通道
      for i in [0..SRC_UNIT]:                  // 16 个输入通道
        dstTemp[j] += (int32_t)src_z[i] × (int32_t)weight_j[i]

  // 去量化:
  for j in [0..UNIT]:
    value = dstTemp[j] × scale_dz[j] × inputScale
          + srcSum × weightBias_dz[j]     // 非对称补偿
          + inputBias × weightKernelSum[j] // 零点补偿
          + bias_dz[j]                     // 卷积偏置

    if INT8 输出:
      value = clamp(round(value), min, max)
      dst[j] = (int8_t)value
    else:
      dst[j] = value  // FP32 输出

权重打包格式

// packWeightAndQuantInfo: [weight][scale][bias] 交错存储

weight shape: [oc/UNIT, blockNum, blockK/SRC_UNIT, UNIT, SRC_UNIT]
scale array:  [blockNum × ocUp4] FP32 值 (跟随 weight)

// blockNum: 分组量化 block 数, 每组独立的 scale/bias
// 好处: GEMM 内核一次 load 拿到 weight + scale + bias, 无间接引用

INT8 Winograd 特殊处理

// ConvInt8Winograd.cpp
// 权重变换在 FP32 域做, 然后重新量化回 INT8

1. dequant: FP32_weight = INT8_weight × quantScale
2. G×g×G^T:   在 FP32 域做 Winograd 权重变换
3. requant:    INT8_weight' = round(FP32_weight' / newScale)
4. precompute: offset = Σ(quanData × (-inputPoint[a]))

执行时:
  输入变换: FP32 (与 FP32 Winograd 相同)
  量化:      MNNFloat2Int8 (FP32 → INT8)
  GEMM:      INT8 GEMM kernel
  输出变换: FP32 (变换回 FP32 域)
  后处理:    MNNMatrixAdd + MNNFloat2Int8

面试重点

INT8 为什么能比 FP32 快？
三重因素: ① 内存带宽省 4× (每个 element 1B vs 4B) ② SIMD 每周期做 2~4 个 INT8 MAC (SDOT/I8MM) vs 1 个 FP32 FMA ③ L1 cache 多放 4× tile, 减少 L2 miss。
去量化 (dequant) 放在 GEMM 内部还是外部？
MNN 放在内部。GEMM 内核累加完后立即做 value = int32_accum × scale + compensation，这样输出直接是 FP32，不需要额外 pass。补偿项 (srcSum × weightBias) 是为了处理非对称量化的零点修正。
为什么需要 blockNum (分组量化)？
单个 scale 对于大权重矩阵精度损失大。把权重分成多个 block，每个 block 独立的 scale/bias，逐 block 累加后 Dequant → 精度更高。INT4 权重 (TurboQuant) 是极端情况: 每 32 个值一个 scale。
SDOT 和 I8MM 的区别？
SDOT (ARMv8.2): 4 个 INT8 点积/周期, UNIT=8 SRU=4。I8MM (ARMv8.6): 8 个 INT8 点积/周期, UNIT=8 SRU=8。I8MM 的 SRU 大一倍 (8 vs 4), 单次内循环计算量翻倍, ~2× 吞吐于 SDOT。

深度总结

✅ 三种量化方案: IDST (单scale) / TF-Style (零点式) / Symmetric (per-channel)
✅ INT8 GEMM = int8 乘 + int32 累加 + FP32 去量化 (在 kernel 内部完成)
✅ 架构相关 Tile: SDOT(8,4,12) / I8MM(8,8,10) / SME2(32,4,16)
✅ 权重打包: [weight][scale][bias] 交错, 一次 load 全拿到
✅ 去量化补偿: srcSum×weightBias + inputBias×weightKernelSum (非对称量化)
✅ INT8 Winograd: FP32 域变换 → 重新量化 → INT8 GEMM → FP32 逆变换
